# Поиск музыки по текстовому описанию: BM25 vs эмбеддинги vs реранкинг

Мини-проект по разговорным рекомендациям музыки: по описанию на естественном языке
(настроение, инструменты, атмосфера) найти подходящий трек. Сравниваем три подхода и
измеряем качество на размеченных данных.

## Постановка

* **Запрос** — текстовое описание музыки («An upbeat pop song with soft female vocal…»).
* **Документ (трек)** — набор тегов-аспектов («pop, soft female vocal, mellow piano, sad»).
* **Релевантный документ** — трек, который описывает этот запрос (один на запрос).
* **Метрики:** Recall@{1,5,10,20}, NDCG@10, MRR@10, 95% доверительный интервал для NDCG@10 (бутстрэп).

## Данные

[MusicCaps](https://huggingface.co/datasets/google/MusicCaps) (Google, CC-BY-SA-4.0):
5 521 десятисекундных клипов, у каждого список аспектов и текстовое описание от музыкантов.
Аудио не используется, только текст. Корпус — все треки с непустыми тегами,
запросы — случайная подвыборка (по умолчанию 500, seed = 42).

Цитирование: Agostinelli et al., *MusicLM: Generating Music From Text*, 2023 (arXiv:2301.11325).

## Методы

| # | Метод | Описание |
|---|---|---|
| 1 | BM25 | лексический поиск (`rank-bm25`) |
| 2 | Dense | bi-encoder `all-MiniLM-L6-v2` + FAISS (косинус) |
| 3 | Hybrid | слияние BM25 и Dense через Reciprocal Rank Fusion |
| 4 | Rerank | из топ-20 гибрида: LLM (Claude, listwise) или cross-encoder |

## Результаты

| Метод | Recall@1 | Recall@5 | Recall@10 | Recall@20 | NDCG@10 (95% CI) | MRR@10 | N |
|---|---|---|---|---|---|---|---|
| BM25 | 0.354 | 0.490 | 0.566 | 0.634 | 0.450 [0.409, 0.484] | 0.414 | 500 |
| Dense (MiniLM + FAISS) | 0.226 | 0.374 | 0.450 | 0.518 | 0.328 [0.292, 0.367] | 0.291 | 500 |
| Hybrid (RRF) | 0.372 | 0.536 | 0.620 | 0.682 | 0.485 [0.446, 0.525] | 0.443 | 500 |
| Hybrid → Cross-encoder | 0.436 | 0.590 | 0.656 | 0.682 | 0.540 [0.500, 0.576] | 0.503 | 500 |

## Выводы

1. **Что выиграло и насколько:** Лучшее качество показал реранкинг **Hybrid → Cross-encoder**. Метрика качества NDCG@10 выросла с 0.450 (у базового лексического поиска BM25) и 0.328 (у плоского поиска Dense) до **0.540**, а MRR@10 достиг **0.503**.
2. **Эффективность гибрида:** Объединение BM25 и Dense через алгоритм RRF (Reciprocal Rank Fusion) оправдало себя: NDCG@10 поднялся до 0.485, что выше любого из базовых методов по отдельности. Это подтверждает, что точное совпадение ключевых слов (BM25) и смысловое соответствие (Dense) отлично дополняют друг друга.
3. **Оправданность реранкинга:** Использование Cross-encoder существенно повысило точность ранжирования верхних позиций (Recall@1 вырос до 0.436 против 0.372 у гибрида). По соотношению «время выполнения / качество» локальный cross-encoder оказался оптимальным выбором для реранкинга топ-20 кандидатов.
4. **Слабая сторона Dense-модели:** Базовая модель `all-MiniLM-L6-v2` уступила традиционному BM25 (Recall@1 составил 0.226 против 0.354). Это связано с тем, что стандартные текстовые эмбеддинги без дообучения (fine-tuning) хуже улавливают специфические музыкальные термины и жанровые теги.

## Ограничения (честно)

* Теги и описания в MusicCaps написаны одними и теми же аннотаторами, поэтому лексическое
  пересечение запроса и документа завышено. Абсолютные цифры оптимистичнее, чем на реальных
  пользовательских запросах; сравнивать методы между собой при этом корректно.
* Один релевантный трек на запрос, остальные похожие треки считаются нерелевантными,
  поэтому метрики занижены для «почти правильных» ответов.
* Реранкер видит только теги, а не аудио и не поведение пользователей.
* Оценка на одной подвыборке запросов; для статистической надёжности см. доверительные интервалы.

## Что не получилось / что дальше

1. **Ограничение текстового поиска:** Модели работают только с текстовыми описаниями и тегами, без учёта самого аудиосигнала. В будущем стоит добавить мультимодальные аудио-эмбеддинги (например, **CLAP**).
2. **Дообучение (Fine-tuning):** Стандартная модель `all-MiniLM-L6-v2` не дообучалась под специфику музыкальных тегов. Следующим шагом стоит дообучить bi-encoder на парах `(описание ↔ теги)` с использованием `in-batch negatives`.
3. **Генерация сложных запросов:** Планируется протестировать генерацию интент-запросов через LLM (например, «что-нибудь спокойное для работы») и оценку качества поиска по методу **LLM-as-judge** для запросов без разметки.
## Запуск

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/prepare_data.py --n-queries 500
python src/bm25_baseline.py
python src/dense.py
python src/rerank.py --backend cross-encoder            # бесплатно
export ANTHROPIC_API_KEY=...                            # Windows PowerShell: $env:ANTHROPIC_API_KEY="..."
python src/rerank.py --backend llm --top-k 20           # платно, ответы кэшируются
python src/evaluate.py
python -m pytest -q
```
